# omp-system

OMP-native project orchestration with isolated worker sessions, digest-bound evidence and recursive harness experiments.

## Status

Implementation in progress against approved F01–F12 plan under `docs/omp-system/2026-10-24/`. Not a completed release; do not install into production/default OMP profile. Isolated SDK repair/review/certification, eight reviewed harness surfaces, core pstack workflows, persisted follow-on learning, source-reference recursion parity, frozen regression rejection and certified local handoff have run. Local Git A/B/A install/load/uninstall has run without inference. Specialized catalog semantic parity, full release acceptance and hosted delivery remain unverified. Evidence and limits: `docs/omp-system/2026-10-24/OMP_ACCEPTANCE_AND_OPERATIONS.md`.

## Requirements

- OMP 18.12.6, whose standalone executable embeds Bun 1.4.3.
- Provider/model credentials configured in the selected OMP profile.
- Git for Git installation; no other agent CLI, WSL or Docker required.
- At least 2 GiB free before lab allocation; dependency installation requires additional space.

## Development without changing other projects

Run `scripts/dev-launch.ps1` in PowerShell. It validates ownership and paths, uses `omp-system-dev`, child-scoped TEMP/cache/environment, and does not change the default OMP profile. `omp-system-install-test` is a separate clean-install profile. Both are opt-in and disposable only with ownership proof. `.lab/` contains private evidence, fixtures and state and is excluded from Git/package distribution.

With explicit operator permission, `scripts/dev-launch.ps1 -UseMainProvider` resolves main OMP's 9router credential in memory, verifies lab endpoint/API match, and passes it only to child environment. It never writes the key to source, logs or profile config. Existing `OMP_SYSTEM_API_KEY` is preserved across lab environment isolation; other OMP/Crews routing variables remain isolated. Main credentials are not used automatically without this flag.

No global OMP/AgentKit update, process termination, config migration or other-project mutation is performed. Profiles do not sandbox arbitrary executable code and cannot isolate CPU/RAM/API quota. Lab concurrency is one.

## Git plugin install

After a verified revision is published:

```text
omp --profile omp-system-install-test plugin install github:DongVienNguyen/omp-system#<verified-ref>
```

`<verified-ref>` is not yet a released ref. For OMP 18.12.6, `--scope project` does not isolate Git installs; use a named profile. Native installer uses embedded Bun and resolves pinned SDK dependencies. No postinstall scripts or manual build/setup are required.

Start a new OMP process in the same profile, then `/omp-system doctor`. Plugin is disabled by default for each canonical project/profile. `/omp-system enable` opts in; `/omp-system run <approved-run-spec.json>` explicitly authorizes a bounded run in that project. `omp_system` model tool exposes only status/doctor; models cannot enable execution through it.

## Execution boundary

Only explicit custom filesystem tools are admitted to code workers. Reviewer gets a fresh private registry, empty ambient context/MCP/extensions/memory and read-only tools. Repository tests execute only after operator authorization bound to exact spec, project, run and deadline. This is **trusted-code mode**, not an OS sandbox. Untrusted scripts/plugins must not be admitted without an external OS security boundary.

Certificates require host-attested execution/review records, current snapshot/policy identities and no blocking findings. Bun tests require nonzero JUnit test selection. Non-test tasks require explicit operator-frozen `runner:'command'` and exit-code proof policy with actual host observation; no `noTestsReason` bypass. See `src/checks.ts` and `src/gate.ts`. A model saying PASS/DONE never certifies; method selection never promotes production policy automatically.

Provider recovery keeps model fixed and advances from requested effort through `low`, `medium`, `high`, `auto`, at most four total attempts. `auto` resolves SDK model default to concrete wire effort; it is not sent literally. Additional attempts consume caller budget and share one deadline. Read-only workers may repeat reads; write-capable workers never replay after tool execution. Cancellation, rate limits, provider authentication rejection (401/403), invalid authority/output and cleanup errors remain terminal. Credential rejection reports `auth_rejected` without retaining provider error payload; operator credential refresh is required, not higher effort. Every attempt retains effort, wire, usage and result; exhausted recovery remains failure. See `src/effort-recovery.ts`, `scripts/effort-recovery-smoke.ts` and `scripts/auth-rejection-smoke.ts`.

Observed auth rejection is retained separately from cleanup failure. `BudgetController.settle` atomically persists a run-level auth stop; later task/helper/retry reservations remain denied after restart. Refreshing credentials does not replay failed work automatically; execution needs new explicit admission. `providerAuthBlocks` exposes this stop in status.
Run budgets require explicit positive `max_output_tokens`, `max_input_bytes`, and `max_output_bytes`; workflow budgets use the same fields, and harness certification requests carry `tokenLimits`. Each worker snapshots these ceilings before dispatch. Output tokens accumulate across provider turns and effort retries; every request receives only remaining `maxTokens`. Helpers inherit explicit ceilings with separate per-worker ledgers; worker-count limits still bound total launches. Input is measured as serialized UTF-8 bytes, not claimed tokenizer usage. Missing usage with nonempty output fails closed. Exhausted workers cannot dispatch pending tools or return oversized failed replies; speculative tools are disabled. Approved harness scripts use the admitted byte ceiling for stdout/stderr capture. `scripts/token-limits-smoke.ts` exercises actual localhost SDK HTTP/SSE turns, partial-output retry, input rejection and blocked tool effects without external provider calls.

`standing <spec>` drains a bounded supplied unit queue through existing `Coordinator`, with verbatim standing orders and executable frozen exit predicate. `standing-resume` requires exact explicit authority and rechecks predicate; interrupted/unknown/blocked state never auto-replays. `standing-cancel` persists cancellation and stops the active owned unit. Program, predicate and inbox records appear in status. This local controller does not grant remote stack/merge authority or replace native OMP scheduling; see `src/standing-controller.ts`.
Each supplied standing unit records durable `standing-iteration` before/after snapshot identities, KEEP/REVERT decision and predicate observation. Failed units remain in isolated Coordinator workspaces; the last accepted checkpoint is retained. KEEP means unit acceptance verified, not authorized Git commit or remote landing.
`delivery <spec.json>` supports local-only `round`, `frontier`, and `frontier-check` policy operations. `round` records operator-attested independent producer/reviewer identities, exact base/head and stable Git patch-id; it is not model-generated proof. `frontier` binds one topology writer and compare-and-set generation to a contiguous local branch/head chain. `frontier-check` requires current-head checks, resolved threads and known mergeability in explicitly supplied observations, rechecks branch/patch identity, executes local `git merge-tree`, and rejects trunk overlap or CI-config drift. It stops at first blocked item. Results are `LOCAL_READY` or `BLOCKED`, never remote certification or merge authority. New patch invalidates verdict; rebase may retain code verdict only when stable patch-id matches; CI still needs new head. No push, rebase, retarget, thread resolution or merge is executed by these operations.

`wake-arm <spec.json>` explicitly arms native OMP follow-ups: `{id,project,standingOrders,intervalMs,maxWakes,deadline,watch?:{path}}`. Current project/profile must be enabled. Uses SDK-managed timers, never a second Coordinator. Idle/queued-message/execution-lease gates and `wake-ack <id>` backpressure prevent overlapping continuation. Final count needs no ACK. `wake-stop <id>`, disable, switch/branch and shutdown clear timers; cold persisted state reports inactive/interrupted and never auto-replays. At most 100 wakes/24 hours; local watched file at most 1 MiB. Wake starts main-agent turns and can spend normal provider quota; it grants no worker/write/merge/publish authority. Frozen predicate and bounded run specifications remain separate. Remote CI/forge watchers and automatic commit/revert are not covered. Explicitly authorized recovery review passed; historical failed review records are retained.

`catalog-operator <spec.json>` also accepts forensic/visual actions with exact sealed project/spec/deadline authority; these actions do not open a model provider:

- `trace`: `{action,id,project,paths,before,after?,heapTarget?,deadline}`. Capture paths must equal entries in `paths`. Parses existing CPU profiles, V8 heap snapshots and Chrome duration-event JSON, optionally gzip; stores queryable samples/frames/nodes/edges in the project SQLite store. CPU source lines are one-based; signed source time deltas remain unchanged and non-monotonic timing is labeled inconclusive. Heap retainer paths exclude weak edges; paired comparisons preserve every aggregate delta. Captures remain unchanged and retained as content-addressed artifacts. Unsupported formats fail without recapture. In-memory JSON ceiling: 256 MiB decoded per capture. Missing allocation/source symbols and causal uncertainty remain explicit.
- `runtime-forensics`: `{action,id,project,endpoint,expectedPid,output,sampleMs,instrumentation:{expression,expected},deadline}`. Exact loopback Node inspector endpoint and PID required. Retains untouched CPU baseline at `output`, then profiles the explicitly approved live evaluation separately at `output+'.probe.cpuprofile'`. This evaluation can mutate the target process; approve only trusted expressions. Failed/started IDs cannot replay automatically. An observation match is not independent causal proof; browser/heap live instrumentation is not covered.
- `visual-baseline` / `visual-compare`: `{action,id,project,baseline,browserExecutable,url,viewport:{width,height,deviceScaleFactor},components:[{name,selector}],harness:[path],deadline}`. Installed Chromium executable and loopback HTTP surface required; isolated ephemeral browser profile, no user browser reuse. Each selector names one component/state. Baseline pixels and harness identity are attested and immutable; compare requires exact browser/URL/viewport/component/harness identity. Any changed pixel or dimensions fails; native compare returns exit 1 on mismatch. Same-origin page resources only; trusted application code, not a browser security sandbox. Migration and publishing remain separate authority.
- `session-history`: `{action,id,project,mode:'list'|'read',session?,all,offset,limit,artifacts:[{path,sha256}],deadline}`. Uses native read-only session APIs in current workspace bucket; checks bounded header before transcript. Defaults to seven days by native modified-time semantics; `all:true` includes older same-workspace sessions. Reads immutable content-addressed transcript snapshot, not live replay. Inherited SHA-256 mismatch routes `reconcile-artifacts`; evidence is point-in-time, not a live filesystem lock. At most 100 returned messages/sessions, 10,000 bucket entries, 16 MiB/session or inherited file. No credentials, services or execution authority restored; native archive transfer remains separate.
- `formal-check`: pins Java/TLC executables and complete supplied input closure by SHA-256, freezes input workspace, checks active property declarations and `{modelSymbol,symbol,path,line}` mappings, runs TLC with one worker/256 MiB heap and supervised deadline, and requires actual named-property counterexample for every requested property. Status `BOUNDED_MODEL_VERIFIED` applies only to supplied model/config; mapping presence does not prove source equivalence or generate a project verification skill.
- `evidence-video`: pins FFmpeg/ffprobe, actual PNG slide bytes and claim-evidence digests, renders silent landscape MP4 with readable holds plus fades, probes duration/dimensions/audio, and extracts every slide for review. Result remains `RENDERED_PENDING_VISUAL_REVIEW`, `verified:false`; word counts, claims and composition need independent review. Output stays in owned state, no publish. Portable lab toolchains are optional operator-supplied executables, never auto-downloaded by plugin.
- `media-catchup`: binds a host-captured immutable native history artifact to reviewed actual-user attribution, last-user-message window, all outstanding user-only calls (including older ones), per-request outcomes and pinned slide evidence. `captureMediaCatchupHistory` captures through existing read-only native session path. Source/content reviews are host-sealed; caller role labels cannot authorize a window. Render failure returns disclosure and calls; no-change returns a short reply without rendering. Video embedding requires independent native/manual review of artifact, every extracted frame, word counts and holds. Output stays outside project. `scripts/media-catchup-smoke.ts <ffmpeg> <ffprobe> <chrome>` exercises native history, actual browser screenshot and render; fixture user attribution is known by construction, not proof of arbitrary transcript attribution.

Runnable checks: `tests/trace-forensics.test.ts` (assert-based); `tests/runtime-forensics.test.ts <node.exe>` (actual owned Node process); `scripts/trace-forensics-smoke.ts <node.exe>` and `scripts/visual-parity-smoke.ts <chrome.exe>` retain real surface evidence in `.lab`. Browser/Node must already exist; no downloads.

## Verification

Use embedded Bun without a global Bun install:

```powershell
$env:BUN_BE_BUN = '1'
& "$HOME/.local/bin/omp.exe" test tests/ src/harness/method.test.ts
& "$HOME/.local/bin/omp.exe" node_modules/typescript/bin/tsc --noEmit
```

Use `scripts/verify.ts --case windows-acceptance` for retained same-source evidence. Native integration tests use explicit deadlines matching their bounded subprocess chains; runner default is60s/test and Windows case has900s total deadline. This is not a provider budget increase or a full-release certificate. Failed or timed-out reports remain evidence.

Native coexistence readiness has a separate 120s cold-start deadline and still requires both SDK sessions to send real snapshots before lifecycle actions. Timeout diagnostics retain per-session startup phases. V8 CPU samples may omit source symbols; runtime forensic capture reports observed attribution without requiring a particular sampled frame or claiming a confirmed cause.

Set `BUN_BE_BUN` only in the child process in automation. Provider-backed scripts spend quota and require admitted budget. Forensic/visual smoke scripts spend no provider quota, but still require exclusive lab resource admission and create evidence in `.lab`. Do not copy credentials into this repository.

Operator workflow, certification, promotion and delivery schemas are owned by `src/workflow-spec.ts`, `src/certify-harness.ts`, `src/promotion-command.ts` and `src/delivery-command.ts`. Local playbook protocols use `src/catalog-semantics.ts` and `src/catalog-local.ts` through explicit `catalog-operator`/`catalog-local` commands; local proof is not full upstream parity. `prepare-branch` creates separate exact-candidate Git worktree/commit; push and PR need separate action-specific approval. Live verifier cases require `--live --admission <json>` with exact case, deadline and worker ceiling. Credentials resolve from selected profile/process environment only; missing `OMP_SYSTEM_API_KEY` must use approved process-local credential source, never repository files or command arguments. SDK retry/replay disabled; explicit primary admission owns retries.
